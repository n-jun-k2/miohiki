# 共通作業ログの構築指示

## 目的
ユーザーとメインエージェント、サブエージェント間の依頼・回答・議論・決定を簡潔に追跡できるようにする。

## 保存形式
`worklog/YYYYMMDD_HHMMSS_{議題}.txt`

1議題につき1ファイル。開始時刻をファイル名に用い、議題名はパスとして安全な短い名前にする。同名衝突時は連番を付ける。UTF-8で保存する。

## 記録例
```text
[2026-11-25 18:00:00] USER -> MAIN
依頼内容

[2026-11-25 18:00:05] MAIN -> algorithm_engineer
実際に渡した依頼

[2026-11-25 18:01:00] algorithm_engineer -> MAIN
実際に返された回答

[2026-11-25 18:02:00] MAIN -> USER
統合結果・最終回答
```

## 共通ルール
- ユーザーの依頼、各 Agent への実際の指示と回答、反論・再検討、最終回答、承認・追加指示・決定事項を時系列で追記する。
- 取得可能な原文を記録する。取得できない内容や時刻は捏造せず未取得と記す。機密情報・認証情報は除外またはマスクし、非公開の内部思考は記録しない。
- メインエージェントのみが書き込む。委譲前・回答受領時などに逐次追記し、過去ログを上書きしない。
- 同じ議題を再開する場合は該当ログを確認して追記する。新しい議題では新規ファイルを作る。再開先が曖昧なら確認する。
- 特定の Skill に限定せず、通常のサブエージェント委譲にも適用する。
- docs/ の仕様正本と worklog/ の議論記録を区別する。ログにある提案を承認済み仕様として扱わない。

## 導入
既存の AGENTS.md とログ規約を確認し、共通ルールとして統合する。既存の規約と衝突する場合は変更案を提示する。各 Skill に重複定義しない。専用 Agent、Skill、スクリプト、複雑なディレクトリ階層は追加しない。
ログの Git 管理方針は既存規約を優先し、未定なら機密性を考慮した案を提示する。無断で公開・コミットしない。
変更案を提示して承認を待ち、承認後に設定を反映する。サンプルの依頼・回答で追記形式を確認し、結果を報告する。
この仕組みは指示ベースであり、Codex の標準セッションログや完全な機械的監査ログの代替ではない。記録できない情報がある場合は明示する。
