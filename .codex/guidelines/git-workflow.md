# Git・GitHub 開発ワークフロー

承認済みの要求と設計・計画に基づき、関連 Issue を確認して重複を避ける。新規 Issue は背景、目的、要件、課題、範囲・対象外、実装方針、完了条件、テスト、依存と未決事項を含む案と計画を提示し、承認後に作成する。ユーザーの指示する範囲を優先する。

GitHub Flow を基本とし、最新のデフォルトブランチから `{type}/{issue-number}-{short-description}` を作る。type は feature、fix、refactor、test、docs、chore、experiment、hotfix。英小文字・ハイフンを使う。未コミット変更や他者の作業を保全し、必要に応じ worktree を利用し、同一ファイルの同時編集を避ける。main への直接コミット・push、force push、git reset --hard、git clean、変更の破棄、保護規則の回避、自動マージは禁止。空リモートの初期化は通常手順と分けて提案し、具体的な承認を得る。

## 新しい作業ブランチの準備

新しい作業を始める前に、現在のブランチ、未コミット変更（ステージ済み・未追跡を含む）、既存 stash と他者の作業を確認する。main に切り替え、リモートを確認して `git pull --ff-only` で最新化し、その main から作業ブランチを作成してから変更する。進行中の同一作業ブランチを継続する場合は、新しいブランチを重ねて作らず、対象と最新性を確認する。main が存在しない、分岐して fast-forward できない、認証・通信・権限に問題がある場合は作業を止めて報告し、履歴を破壊しない。

手順を踏まずに変更してしまった場合は、所有者と退避・移動対象を確認し、ステージ済み・未追跡を含む必要な変更を識別可能な名前の `git stash push --include-untracked` などで退避する。無関係な変更や既存 stash を巻き込まず、対象を切り分けられない場合は作業を止めて確認する。退避内容・元ブランチ・stash の識別子を確認した後に main へ切り替え、`git pull --ff-only` して新しい作業ブランチを作る。そのブランチに対象の stash を `git stash apply --index <識別子>` で復元し、差分・未追跡・ステージ状態を確認する。復元できない場合は stash を残し、競合を記録して対応する。確認前に `pop`・`drop`・`clear` を使わず、無関係な stash を変更しない。退避・復元が難しい変更（無視ファイル等）は破棄せず、対応を確認する。

設計・計画・Issue 案の承認後、承認範囲に含まれるブランチ、実装、検証、独立レビュー、commit、push、PR 作成まで連続して進める。操作の実行権限は別に必要であり、リモート設定変更や第三者への通知は承認範囲に含まれない。仕様変更、計画外変更、重大な検証失敗、解決できない競合や権限不足は停止し報告する。

コミットは `<type>(<scope>): <description>` を基本とし、type は feat、fix、refactor、test、docs、chore、perf、ci、build。対象ファイルを個別に確認して登録し、意図しない差分・生成物・機密を除き、`git diff --check` と必要なテスト、承認済み計画との整合を確認する。

必要な検証と独立レビュー後、Critical を解消し Warning と未検証の理由を明示して PR を作成する。PR は `<type>(<scope>): <description> (#<issue-number>)` を基本とし、目的・Issue・要件・変更・設計判断・検証・レビューと対応・未解決・未検証・互換性を記載する。Issue の対応完了時のみ `Closes #番号`、部分対応は `Refs #番号` を使う。必要テストと完了条件、ベースとの競合を確認し、重大問題が残れば通常 PR を作成せず報告する。CI 未完了は明示し、成功前にマージしない。最終承認・マージは人間が行う。

すべての PR は作成後、ドラフトを含めてメインが自己レビューする。GitHub 上のベース・HEAD・差分、タイトル・本文と Issue、承認範囲、検証・独立レビューの記載、CI・競合状態を再確認し、指摘・修正・未解決・未検証を共通ログと最終報告に記録する。結果を PR 本文に反映する場合は承認範囲と権限に従う。問題の修正後は必要な検証を再実行し、変更された PR を再確認する。重大な問題や未完了の CI は成功扱いせず、必要に応じドラフトで報告する。これは PR 作成前の独立レビューに追加する自己確認であり、GitHub のレビュー承認や人間の最終承認を代替しない。

権限・認証・環境等の問題で操作を完了できない場合は、実行済みと未実行、原因と停止位置を報告し、ユーザーが手動で続行できるよう、実行環境・作業ディレクトリ・前提条件・状況に合う具体的な CLI・確認方法・再開点を示す。破壊的操作や保護回避を勧めず、認証情報を会話に貼らせない。手動操作の成功は確認できるまで未完了とする。

実行と判断のログは AGENTS.md の共通ルールに従い、Issue 番号・コミット SHA・PR URL を記録する。リモートの権限や保護設定の変更には別途具体的な承認が必要。
