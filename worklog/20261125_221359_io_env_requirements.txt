1. 「最新優先」は未採用候補。最後に到着した結果が最新とは限らない。例：フレーム 100 の結果後に 90 が遅延到着すると、到着順上書きで表示が過去へ戻る。実行・カメラ・世代ごとに結果の対象フレーム順を検証し、逆転・重複・旧世代を記録して採用するか破棄するか決める。SOT が同一フレームを複数回更新する可能性は未確定で、その場合は別の版情報が必要。
2. 取得側でフレームを捨ててから保存分岐すると「MOT が飛ばしたものも保存」の合意と矛盾する。保存経路の対象を取得成功後・MOT 向け間引き前とし、物理カメラが出力した全フレームと IO が実際に取得した全フレームを区別する。保存速度不足時にブロックすれば、ライブカメラのドライバ等で取得前の欠落や遅延が生じ得るため、待機が完全保存を保証するわけでもない。保存欠落、取得側欠落、障害停止を各々可視化する方針と、どれを許容するかは未決。
3. 保存 ON/OFF と MOT 間引きの試験は、画像ファイル数だけでなく取得 ID 集合、MOT 受信 ID 集合、保存成功/失敗 ID 集合を比較する。意図的に遅い書込み・容量不足を注入し、キュー上限到達後も無制限にメモリが増えないことと、選んだポリシーが観測可能であることを検証。ただしそのポリシー自体は未決。
