# Round 1: 独立検討（実施済み）

## requirements_analyst
開発者・評価者による観測差替え、空観測、新規・消失・復帰、系列単位の実行を想定。観測契約と ID の範囲、状態・寿命、不正入力を定め、固定シナリオで受け入れる案。単一カメラ同期から始める案と非同期・複数カメラへの初期対応を比較。境界不明と過度な初期範囲がリスク。映像取得・表示を範囲外とする案は既存合意の見落としで、Round 2 で撤回。出典: README、依頼文。

## algorithm_engineer
観測の出所・対象フレーム・時刻・座標と欠落理由を保持し、未実行と成功ゼロを区別。ID 維持、観測不足時の寿命、SOT 再起動後の旧結果排除を提案。同一フレーム対応、IoU、一対一割当、4 状態、実行・カメラ単位 ID は候補。密集・遮蔽、SOT drift、遅延による不整合がリスク。遅延結果破棄と過去再処理、IoU 最適割当と貪欲法を比較。これらの固定は Round 3 で撤回。出典: README、既存要件。

## evaluation_specialist
観測再生による中核の再現性、状態遷移・欠測・交差・再起動試験、追跡精度と遅延・ドロップ・資源の別評価を提案。HOTA、IDF1 等は候補。GPU・外部サービス不要の中核試験と環境結合試験を分ける。正解規約、負荷、目標値が未定で、測定なしに性能を保証できない。JPEG 保存だけでは推論の完全再現は保証されない。出典: README、既存要件。
