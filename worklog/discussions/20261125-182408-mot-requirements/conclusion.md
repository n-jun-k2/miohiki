# 統合結果（提案、未承認）

## 既存合意
リアルタイムカメラを対象とし、IO_ENV が取得・表示・映像保存、MOT_ENV が進行管理・観測集約・Track 管理・SOT 制御、DET_ENV/SOT_ENV が各処理を担当。中核は通信・進行管理と分離。処理が追いつかなければフレームを飛ばし、Detection/SOT の間隔は MOT が処理したフレーム数を基準とする。表示は最新結果をフレーム同期せず使う。Detection による SOT 補正時は既存 SOT を停止し新たに開始、Track ID を引き継ぐ。映像保存の有無は設定可能で、保存時は取得フレームを JPEG 連続保存し、飛ばしたフレームも対象とする。詳細は [既存要件](../../../agent_log/requirements.md)。Docker/gRPC は構想。

## 利用者・ユースケースの仮説
独自 Detection/SOT を組み込む開発者と方式を比較する評価者を想定。複数観測から対象を生成・更新し、遮蔽や欠測を経て終了させる。異なる観測器の接続や記録の再生・評価を行う。利用者、対象、初期版範囲は未確認。

## 機能要件候補
1. 観測の種別・出所、対象フレーム・時刻、座標系、BBOX、利用可能な属性を扱い、SOT 結果と対象 Track・起動の関係を識別できる。
2. 未実行、成功ゼロ、未着、期限超過、失敗、欠落を意味上区別でき、観測間の重複・競合・未対応と異時刻の結果を定められた規則で扱う。公開 API の状態数は固定しない。
3. Track の生成・更新・観測不在・終了を管理し、ID、BBOX の有無と出所・対象時刻、状態、寿命情報を取得できる。状態の意味、ID の範囲、寿命の単位・判定は別途決める。
4. SOT の開始・停止・再起動と Track の関係を管理し、再起動前の遅延結果の扱いを定めて ID 継承を守る。
5. 処理間隔、保存等の既存合意を設定し、結果・入力の対応と判断を解析可能に記録する。記録項目、保存期間、機密性の扱いは未決定。

## 非機能要件候補
- 中核は外部モデル・GPU・通信サービスなしで検証可能とし、必須依存と任意依存を明示する。性能値は未決定。
- 時刻、入力、到着順、期限・欠落、設定、乱数、初期状態を固定した中核再生の再現範囲を規定する。実システムの完全再現を保証しない。
- 精度、ID 切替、出力の鮮度、撮影から出力までの遅延、フレーム破棄率、CPU/GPU・メモリを、対象負荷と環境を記録して評価する。時計の同期誤差も考慮する。
- 障害・遅延・不正入力の扱いを定義し、構成や観測結果の追跡可能性を確保する。耐障害水準、長時間稼働、データ保持は未決定。

## 受け入れ条件候補
- 固定シナリオで生成・更新・欠測・終了、複数観測の競合、ID と BBOX・状態・寿命出力を決定した規則どおり検証する。
- 検出未実行とゼロ、失敗と未着、到着順逆転、旧 SOT 応答、フレーム飛びを注入し、合意した時間・状態規則を検証する。
- 結合試験で処理済みフレーム基準の間隔、負荷時フレーム飛ばし、非同期最新結果表示、保存設定、SOT 再起動時 ID 継承を確認する。
- 正解データ、出力時刻と遮蔽等の評価規約、対象環境と数値閾値を決めた後に精度と速度の合否を判定する。処理フレーム限定精度、全取得フレームでの有効出力率、表示鮮度は別々に報告する。

## 比較と残るリスク
遅延観測の破棄は簡単だが情報を失い、予測は誤差を伴い、遡及再計算は計算費用と既出力の訂正規則が必要。IoU・一対一割当は単純だが交差や遮蔽に弱い。外観情報は改善の可能性がある一方、依存・計算量・データ条件を増やす。いずれも未採用。単純な重複融合は密集対象を誤統合し得る。既存合意に反するため、映像取得・表示や SOT 制御をシステム全体から除外する案は採用しない。ユーザー承認前につき本書の新規候補はすべて未決定。
