# TAM の組み込み検討

ユーザーは当初、論文 [3D zebrafish tracking with topology association](https://doi.org/10.1049/ipr2.12694) の TAM の組み込みを希望。その後、2026-11-25 に、まず SOT と Detection の対応付けの問題を確認して評価候補を絞る方針を承認した。TAM は評価候補として残し、初期構成への組み込みは確定しない。詳細は [承認済み方針](../docs/requirements/sot-detection-evaluation.md)。

論文では隣接時刻の対象の点群から候補を一つずつ除外し、残りの集合の Hausdorff 距離と方向類似度に基づく行列を算出し、割当を行う。対象数が比較的安定し、頻繁に画面を出入りしない場合が適用条件とされる。2D の実験もある。3D 再構成の多視点再対応付けは TAM 本体とは別工程。

## 組み込み案（参考・未承認）

各 Track の SOT の BBOX 中心群と同一対象時刻の Detection の BBOX 中心群から、TAM に基づく対応候補を作る。候補を受け入れ条件で検査し、採用した Detection で SOT を停止・再起動し Track ID を継承する。未対応 Track の維持・終了、新規 Detection の生成を別途判定する。これは論文を SOT と組み合わせた提案であり、論文の方式そのものではない。既存の最新結果非同期表示は維持する。

## 未決定・検証事項

- 論文の数式・正規化・割当・閾値の忠実な再現と、2D への適用方法。空集合・1対象、同一点、ゼロ除算の扱い。
- SOT と Detection の対象時刻の整合、遅延・飛ばし、処理済みフレーム間隔。異時刻を暗黙に混ぜない。
- 出入り、検出漏れ、誤検出、複数検出器の重複、SOT drift、画面全体の移動に対する信頼性とフォールバック。TAM の採用判定・拒否基準は未定。
- 検出対応が成立した場合に毎回再起動するか、ずれが大きい場合に限定するか。停止失敗と旧世代応答の扱い。
- 対象数に対する計算量と実測遅延。IoU 等の基準方式と同じ映像・検出結果・SOT 条件で ID 切替、IDF1/HOTA、誤対応、補正回数、速度を比較する。正解規約・目標値は未決。

性能向上は未検証。実装・技術選択・適用条件は未承認。

## 出入りへの前処理案（検討中）

ユーザー提案: 既存 Track/SOT と Detection を事前に選別し、出入りによる TAM への影響を減らす。明確な対応は別途確保し、出入り・欠測・誤検出が疑われるものは TAM 入力から一時除外する候補。ただし対応済みの点を両方から取り除くと点群の構造情報も失われるため、残して文脈に使う案と比較する。除外は Track の終了や Detection の破棄を意味せず、候補に戻せるよう理由付きで保持する。

事前対応付けそのものの誤り、遮蔽と退場の区別、孤立点による Hausdorff 距離への影響、少数点や対称配置、時刻不整合を検証する。入力点数が同じでも同一対象集合とは限らず、出入り問題の解決は保証できない。候補の採否・棄却条件、出入りの猶予と再検討、TAM 不適用時の処理は未決定。
