## 目的

リアルタイムのカメラ映像を対象に、Detection と SOT の結果を基に複数対象を追跡する。さまざまな SOT の実行環境を利用できる構成とし、MOT の中核処理の依存をなるべく減らす。

## 合意済みの方針

### 環境と役割

| 環境 | 役割 |
| --- | --- |
| IO_ENV | カメラ映像の取得・提供、追跡結果の取得と表示、映像の保存 |
| MOT_ENV | 処理の進行管理、Detection と SOT の結果の集約、Track ID と追跡状態の管理、SOT の制御 |
| DET_ENV | Detection の管理・実行と結果の返却 |
| SOT_ENV | 外部で SOT を起動・実行し、推定結果を返却する |

カメラから IO_ENV を経由して MOT_ENV にフレームを渡す。MOT_ENV が DET_ENV と SOT_ENV に実行を要求し、結果を受け取る。MOT_ENV は SOT の開始・停止などを制御する。異なる SOT 環境を利用するため、Docker 上で gRPC により管理する構想である。MOT の中核処理と通信・進行管理は分離する方針。

### 処理と表示

- 初期構成では各 Track の SOT を追跡の主体とし、Detection を新規対象の発見と、対応が明確な Track の確認・補正に使う。曖昧な Detection は無理に補正に使わず、その扱いは今後検討する。
- まず SOT と Detection の対応付けで実際に生じる問題を観察し、その結果に基づいて対策・評価候補を絞る。TAM は評価候補として残し、初期構成への組み込みは確定しない。詳細は [承認済み方針](../docs/requirements/sot-detection-evaluation.md)。
- Detection と SOT の実行間隔はパラメータで指定できるようにする。間隔は MOT_ENV が実際に処理したフレーム数を基準とする。
- リアルタイム性を重視し、処理が追いつかない場合はフレームを飛ばす。
- IO_ENV は MOT_ENV が持つ最新の追跡結果を取得し、BBOX と Track ID を映像に表示する。結果を映像フレームと同期して待つことはせず、時間差があってもそのまま表示する。
- SOT の位置を Detection で補正する場合、既存の SOT を停止し、Detection の BBOX を初期位置として新しい SOT を開始する。MOT の Track ID は引き継ぐ。

### 保存と解析

- 各コンテナのログを蓄積する場所を設ける。主な目的は追跡結果の精度・挙動の確認。
- 映像の保存はパラメータで有効・無効を指定する。保存する場合は、IO_ENV で取得したフレームを JPEG 画像として連続保存する想定。MOT で飛ばしたフレームも保存対象とする。
- 画像の保存先は日付とフレーム番号で整理する。再起動や複数カメラによる重複を避けるため、実行 ID・カメラ ID を途中に含める案がある。

## 提案中の設計

以下は検討材料であり、確定事項ではない。

- 各フレームにカメラ ID、フレーム ID、撮影時刻を付け、各環境の結果を照合する。処理順の番号も記録する。
- Detection を実行しなかった場合と、実行して検出がゼロだった場合を区別する。
- 解析用に Detection と SOT の結果、MOT の出力、対応付けの判断、SOT の開始・停止・再起動を記録する。モデルが出力しないスコア等は任意とする。
- 記録をコンテナ外のストレージに保存し、環境ごとに整理する。
- Detection と SOT の BBOX の切り替えや、同一クラスと BBOX の IoU を基準にした対応付けは具体案であり、未合意。
- 画像保存時の JPEG 品質を設定できるようにする。

## 未決定事項

- Detection と既存 Track の対応付け方法、閾値、複数候補の扱い。
- Track の新規作成、維持、消失・終了の条件と Track ID の採番方法。
- 出力 BBOX の選択方法、SOT の再起動・停止条件。
- Detection・SOT とも実行しないフレームや、結果の欠落・遅延・エラー時の扱い。
- フレームを飛ばす際の選択方法、SOT の処理間隔、開始・再起動に使用するフレームの保持方法。
- 各環境間の具体的な通信仕様、フレームの受け渡し、結果取得の周期。
- 解析データの形式、保存期間、画像保存が追いつかない場合の扱い。
- 追跡対象の種類、対象数、クラスの扱い、求める速度・精度。
