# 調査報告・文書化ワークフロー構築案（承認済み）

2026-11-26。対象: [setup-reporting-workflow.md](../prompts/setup-reporting-workflow.md) と、操作が権限等で失敗した際に手動 CLI と再開手順を示すユーザー指示。既存の共通作業ログ、議論記録、承認済み資料の扱いは維持する。

## 現状と役割分担

既存の `requirements_analyst`、`mot_researcher`、`evaluation_specialist` は専門的な要件分析・調査・評価を担当し、ファイル編集は禁止。メインは各意見を統合し、`worklog/*.txt` を管理する。汎用 `worker` は担当範囲内の実装向けで、報告書専任の責務・禁止事項がない。既存の `flow-discussion` 等は議論記録を作るが、読み手別の報告書作成は担っていない。

提案: `project_secretary` は文書化を担当し、主張・数値・決定状態・出典を追跡できる報告書を作成する。報告書に必要な指定ファイルのみ編集し、ソースコード、要件・仕様の確定、Git・Issue・PR・外部送信を行わない。メインが対象資料・編集範囲・読者・目的を渡し、内容を統合・確認する。Agent の編集制約は行動指示であり独立した権限隔離ではない。

## 変更対象

| ファイル | 内容 |
| --- | --- |
| `.codex/agents/project_secretary.toml` | 報告担当の目的、入力、出力、根拠、事実と推測・確定と提案・実測と期待の区別、編集範囲と禁止事項 |
| `.agents/skills/wf-report/SKILL.md` | 単独利用できる報告書作成。依頼・読者・元資料を確認し、必要時のみ `worklog/reports/YYYYMMDD_{議題}.md` に保存。既存報告は無断上書きせず、報告目的に合わせて構成 |

議論担当専門 Agent の編集禁止は維持し、`project_secretary` の報告書編集のみ例外として明示する。議論本体の `worklog/discussions/`、`worklog/*.txt`、承認済みの `docs/` は従来の手順と管理者の責務を維持する。報告書を docs の正本に移すときは変更案を提示し、承認状態を確認する。

## 失敗時の手動 CLI 案

実際に失敗した操作について、適用環境・ディレクトリ・実行前提・具体的なコマンド・期待される確認結果を示す。たとえば HTTPS 認証不足で `git push` が失敗した場合は `gh auth status` と `gh auth login`、該当ブランチへの `git push -u origin <実ブランチ名>`、`git status -sb` などを、その状況に合わせて案内する。ユーザーにトークンを会話へ貼らせない。実行結果を確認するまで完了扱いにせず、別手段が利用可能なら権限と意図を確認した上で適切に使う。これらは例であり、権限不足の種類に合わないコマンドを機械的に提示しない。

## 検証計画

Codex CLI 0.172.0 と既存定義に整合する TOML・Skill の形式と参照を検証する。サンプルは一時作業領域に用意した架空の結果だけを入力し、実際の `project_secretary` で報告書を作成して内容・出典・未検証の区別を確認する。利用できない場合は未実施と明記し、単一 Agent の役割演技で置き換えない。手動 CLI は一時 Git リポジトリや読み取り専用確認で安全に検証し、リモートに書き込まない。生成されたサンプルをプロジェクトの実績や決定にしない。

## 承認・作業状態

ユーザーは本案と作成後の PR 作成を承認した。既存の未コミット差分と stash は保全し、main を `git pull --ff-only` した後、新規ブランチ `chore/reporting-workflow-setup` を作成した。アプリケーションコード・既存確定仕様は変更しない。
