# 開発段階のエージェント構成方針（承認済み）

2026-11-25 にユーザーが承認。実装には利用可能な汎用 `worker` を使い、専用定義は追加しない。既存合意は [現在の要件](requirements.md) と [SOT・Detection の方針](../docs/requirements/sot-detection-evaluation.md) を参照する。

## 基本方針

- メインが要求・設計の整合、作業分割、統合、検証、ユーザーへの報告を担当する。単純な変更はメインだけで行い、独立して進められる作業や専門的レビューが必要な場合に委譲する。
- 機能ごとに Agent を増やさず、既存の専門 Agent を設計・調査・レビューに再利用する。実装のために既存の読み取り専用 Agent の禁止事項を緩めず、実装担当を別に設ける。
- 要件の議論が終わったことと、すべての詳細仕様が決まったことは区別する。対応付け、状態遷移、通信等の未決事項は実装時の仮定として明示し、影響が大きい判断は設計・確認する。TAM の初期導入を前提にしない。

## 役割

| 役割 | 主な責務 | 編集権限・境界 |
| --- | --- | --- |
| メイン | 作業計画、担当と境界の割当、統合、最終検証・報告 | 全体の編集と共通ログの唯一の記録担当 |
| 実装担当（汎用 worker） | 指定された機能と必要なテスト・文書を実装 | 依頼ごとに明示されたファイルを所有し、他者の変更を戻さない。仕様の独断確定・外部への書き込みはしない |
| algorithm_engineer（既存） | SOT・Detection の扱い、Track の状態・対応付けのレビュー | 既存どおり読み取り専用。実装方式の独断確定はしない |
| software_architect（既存） | 中核と通信・進行管理の境界、環境間契約の設計・レビュー | 既存どおり読み取り専用 |
| evaluation_specialist（既存） | 試験観点、評価データと再現条件、精度・遅延の測定方針 | 既存どおり読み取り専用。実験結果がない性能を保証しない |
| critical_reviewer（既存） | 要件との矛盾、障害、変更範囲、検証漏れの独立レビュー | 既存どおり読み取り専用 |
| mot_researcher / requirements_analyst（既存） | 先行研究調査 / 要求の確認が必要な場合に利用 | 既存どおり読み取り専用 |

実装担当は単一の汎用ロールを基本とし、MOT 中核、外部アダプタ、テストなどは案件ごとの担当範囲として渡す。領域固有のロールは、繰り返し必要な専門知識や明確な責務境界が確認された場合に限り検討する。並列数や起動の可否は実行環境に従う。

## 進め方

承認済みの開発工程と独立レビューは [開発ワークフロー構築案](development-workflow-proposal.md) と `flow-development` を参照する。計画・実装・試験・検証・レビューは対応する `wf-*` Skill も個別に利用できる。

1. 既存要件と未決事項を確認し、最初に実現する範囲と検証可能な条件をまとめる。中核と外部環境の入出力契約など重要な設計は、必要に応じて `flow-design` で検討し承認を得る。設計議論では従来の専門 Agent を使う。
2. 契約と受け入れ条件を基に作業を分割し、各実装担当に目的、関連資料、所有ファイル、変更可能範囲、他担当との接点、必要な検証、報告内容を渡す。同じファイルの同時編集を避ける。
3. メインが実装を統合し、対象のテストと結合確認を行う。SOT の再起動時の ID 継承、未実行と検出ゼロ、遅延した旧結果、交差・遮蔽などは仕様化された範囲で検証する。未決の振る舞いを合意済みとみなさない。
4. 必要に応じて既存の専門 Agent に変更・検証結果をレビューさせる。問題や未検証事項を解消または記録し、実装内容と制限を報告する。

エージェント間の作業ログは [AGENTS.md](../AGENTS.md) の共通ルールに従い、メインのみが原文を追記する。議論用 Skill が必要とする成果物は別途維持する。README の利用方法・環境の更新も同ファイルの作業方針に従う。

## 定義作成時の確認

- 実装ロールの目的、入力、出力、編集・実行範囲、他者の変更の尊重、報告と停止条件を定義する。実装担当は利用可能な既存の汎用 worker で足りるか先に確認し、足りなければ専用定義を追加する。
- 既存の Agent 設定や Skill と責務・権限が矛盾しないことを確認する。`agent_log/multi-agent-workflow.md` の議論用の編集禁止は専門 Agent に適用し、実装担当には上記の限定的な編集範囲を与える。
- 設定追加後に構文と環境での認識を確認し、限定的な作業で編集・検証・報告を試す。権限分離の強制ではなく行動指示であること、実施できなかった確認を明示する。
